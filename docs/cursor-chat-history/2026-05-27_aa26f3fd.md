## Telefonda 19 numaralı build’i kurma

1. **TestFlight** uygulamasını açın (App Store’dan yükleyin).
2. Sorunlu olan uygulamayı (OmniFolio / portföy uygulaması) seçin.
3. Aşağı kaydırın; **“Önceki Sürümler”** / **“Previous Builds”** bölümünü arayın.
4. Listede **Build 19** görünüyorsa yanındaki **Yükle** / **Install**’a dokunun.
5. Kurulum bitince uygulamayı TestFlight’tan veya ana ekrandan açın.

Build 21 zaten yüklüyse, 19’u yüklediğinizde TestFlight çoğu zaman **üzerine yazar** (aynı bundle id); ayrıca “iki sürüm yan yana” olmaz.

## “Önceki Sürümler” görünmüyorsa

Bu durumda telefondan **kendiniz** 19’u seçemezsiniz. Olası nedenler:

| Durum | Ne olur |
|--------|---------|
| Build 19 **90 günden eski** | TestFlight süresi dolmuş; listede çıkmaz |
| App Store Connect’te 19 **devre dışı** / silinmiş | TestFlight’ta görünmez |
| Sadece **en son birkaç build** gösterilir | Apple her zaman tüm eski build’leri listelemez |
| Hiç 19’a davet edilmediniz | Nadiren; genelde tüm test build’leri aynı gruba gider |

Bu durumda yapılacaklar **sizin tarafınızda değil**, geliştirici / App Store Connect tarafında:

- [App Store Connect](https://appstoreconnect.apple.com) → uygulama → **TestFlight** → Build **19** hâlâ var mı, **Expired** değil mi kontrol edilir.
- Gerekirse 19’un kodundan **yeni bir build** (ör. 22) alınıp TestFlight’a yüklenir — pratikte en hızlı çözüm budur.

## Dikkat: “19” build numarası mı, sürüm numarası mı?

TestFlight ekranında iki farklı sayı görülebilir:

- **Version** (ör. 1.0.0) — kullanıcıya görünen sürüm
- **Build** (ör. 19, 21) — her yüklemedeki artan numara

Siz muhtemelen **Build 19**’u kastediyorsunuz; listede de genelde “Build 19” yazar.

## 21’de ne sorun çıktı?

Repoda TestFlight için sık görülen konu **Supabase ortam değişkenlerinin EAS’ta tanımlı olmaması** (`docs/EAS-ENV.md`); 21’de uygulama açılmıyorsa veya oturum açılmıyorsa bu da kontrol edilmeli.

Özet: Önce TestFlight → uygulama → **Önceki Sürümler** → Build 19 → Yükle. Orada yoksa, 19’u telefona geri getirmek için yeni bir TestFlight build’i gerekir.

## ASSISTANT

Bu hata büyük olasılıkla **Expo Go + LAN** (`npx expo start --go --lan`, port 8082) kullanımından kaynaklanıyor. Google hesabı seçildikten sonra Supabase, uygulamaya `exp://192.168.x.x:8082/...` gibi bir adrese yönlendirmeye çalışıyor; Supabase bu tür **yerel ağ IP’li** redirect URL’lerini reddediyor ve tarayıcıda “sunucuya ulaşılamadı” görünüyor.

## Ne yaptım

1. **LAN tespiti** — Google’a basmadan önce bu durum yakalanıyor; ekranda net bir uyarı gösteriliyor.
2. **TestFlight için sabit redirect** — production build’lerde her zaman `omnifolio://oauth-callback` kullanılıyor.
3. **Google OAuth iyileştirmesi** — URL önceden hazırlanıyor, oturum kontrolü güçlendirildi.
4. **Ağ hataları** — “sunucuya ulaşılamadı” benzeri mesajlar daha anlaşılır hale getirildi.

## Expo Go’da Google girişi için (şimdi dene)

**Seçenek A — Tünel (önerilen)**

```bash
npm run start:tunnel
```

Metro konsolundaki `exp://…` adresini:

1. **Supabase** → Authentication → URL Configuration → **Redirect URLs**’e ekle
2. İsteğe bağlı `.env` dosyasına yaz:
   ```
   EXPO_PUBLIC_OAUTH_REDIRECT_URL=exp://....../--/oauth-callback
   ```
3. Metro’yu yeniden başlat

**Seçenek B — TestFlight / gerçek build**

TestFlight’ta `omnifolio://oauth-callback` zaten kullanılıyor. Supabase Redirect URLs listesinde bu adresin olduğundan emin ol.

## Şifremi unuttum eklerken ne bozuldu?

### 1. Ekran uzadı, alt butonlar kırpıldı
Şifremi unuttum ile gelen ekstra parçalar:
- “Şifremi unuttum” linki
- `forgot` modu (açıklama, farklı buton, “Girişe dön”)
- Bazen bilgi kutusu

Bunlar ekranı **~80–120 px uzattı**. `flex: 1` + **kaydırma olmayan** `View` kullanıldığı için taşan kısım **görünmez** oluyor — Apple en altta olduğu için “satır kayboldu” gibi görünüyordu.

### 2. Hata mesajının yeri değiştirildi
Google (Expo Go + LAN) hata verince **çok uzun** bir metin çıkıyordu. Bunu butonların **üstüne** koyunca:
- Google + Apple aşağı itildi
- Apple tamamen ekran dışına çıktı

Build 1’de hata **butonların altında** — butonlar her zaman görünür kalıyor.

### 3. “Düzeltme” denemeleri asıl sorunu büyüttü
Dokunma sorunlarını çözmek için eklenenler ayrı problemler yarattı:

| Değişiklik | Etki |
|------------|------|
| `ScrollView` | Expo Go + `GestureHandlerRootView` ile alttaki butonlarda ilk dokunuş kaçabiliyor |
| `Pressable` / gesture-handler `TouchableOpacity` | Normal `TouchableOpacity` yerine farklı dokunma davranışı |
| `disabled={busy}` + Apple sheet iptali | iOS’ta `disabled` bazen sıfırlanmıyor, buton “ölü” kalıyor |
| `socialKey` ile yeniden mount | Gereksiz karmaşıklık, flicker |
| Google OAuth prefetch / `WebBrowser.warmUpAsync` | Ek async iş — doğrudan bozmaz ama state karmaşasına yol açtı |

Yani zincir şöyleydi: **şifremi unuttum → ekran uzadı → layout bozuldu → touch fix denemeleri → daha da bozuldu**.

### Current row structure (summary)

```
┌─────────────────────────────────────────────────────────┐
│ [Icon circle]  SYMBOL              12,345 TL (+1.23%)   │
│                123.45 TL           ▲ +120 TL            │
└─────────────────────────────────────────────────────────┘
```

- **Left:** circular icon (Ionicons or FX image) + symbol (bold) + unit price subtitle
- **Right:** total value with **inline** percentage in parentheses on line 1; line 2 = caret + signed change **amount** (not % alone)
- P/L mode follows hero pills (daily vs all-time; TL vs USD)

This is close to Robinhood but differs in:
- Right line 1 mixes value + % on one line
- Right line 2 shows amount, not a clean green/red P/L line (often % + amount in RH-style apps)
